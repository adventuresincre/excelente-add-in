# Security policy

## Reporting a vulnerability

Please do not open a public issue.

Use GitHub's private vulnerability reporting on this repository
([Security tab, "Report a vulnerability"](https://github.com/adventuresincre/excelente-add-in/security/advisories/new)),
or write to us at <https://www.adventuresincre.com/contact-us/> with "Excelente
security" in the subject.

Tell us what you found, how to reproduce it, and what an attacker gets out of
it. A proof of concept helps. If you are not sure whether something counts,
report it anyway and we will work it out together.

We will acknowledge within three business days and give you an assessment within
ten. If we fix it, we will credit you in the release notes unless you would
rather we did not.

## What is in scope

This repository, and the hosted instance at
[excelente.aiedge.ac](https://excelente.aiedge.ac).

Things we care about most:

- Anything that exposes a user's OpenRouter API key beyond their own browser
- Anything that lets a workbook's contents reach a party other than the model
  provider the user selected
- Cross-site scripting in the task pane, including through model output,
  workbook cell contents, or a skill file
- Prompt injection that escalates into a real action, meaning a write to the
  workbook or a network call that bypasses tool approval
- Anything that lets a connector or MCP server act outside the permissions the
  user granted it

## What is not in scope

- Model output being wrong. It will be. That is what
  [verify-model-outputs](apps/excel-addin/skills/verify-model-outputs/SKILL.md)
  and the whole review layer exist for, and it is not a security issue.
- An agent writing something you did not want into your workbook after you
  approved the tool call. Approval is the control. Use Excel's undo.
- Reports generated by an automated scanner with no demonstrated impact.
- Denial of service through volume against the hosted instance.
- Missing security headers with no exploit path attached.

## How the add-in handles your data

Useful context for anyone assessing this:

Your OpenRouter API key is stored in `OfficeRuntime.storage` on your own
machine. Office sandboxes that storage per add-in, so another add-in cannot read
it. It is **not encrypted at rest**. We have deliberately not claimed otherwise:
it is a known defense-in-depth gap, it is documented in
`apps/excel-addin/src/core/storage/README.md`, and a report that we store it
badly is not news to us. A report that something else can *reach* it very much
is.

The key is sent to OpenRouter and to nothing else. Workbook content goes to the
model provider you selected, through OpenRouter, for the requests you initiate.
We do not proxy, log, or retain it.

The add-in requests `ReadWriteDocument` permission because it writes to cells.
Every write is gated by tool approval in the task pane.

If you connect an MCP server, that server sees what the agent sends it. Connector
presets in this repository point at endpoints we run or endpoints we trust, but
you can add any server you like, and you should treat that the same way you treat
installing anything else.

## Safe harbor

If you make a good faith effort to follow this policy, we will not pursue legal
action over your research. Please do not access, modify, or destroy data that is
not yours, and give us a reasonable window to fix things before you publish.
